## Per-finding detail

### 1 (S1-3) — P0 — v5->v6 migration leaves tokens in 0644 config.json.bak

**Where:** [src/cmd/factory.go:119](https://github.com/futurehomeno/edge-easee-adapter/blob/8368b0759d1703a9a21b53566783d61d630bd632/src/cmd/factory.go#L119) · **Verdict:** CONFIRMED · **Pre-existing in v2.8.0:** no · **Prior review:** none

The v5->v6 credentials migration leaves the pre-migration config.json — still holding the plaintext accessToken and refreshToken it exists to remove — behind as data/config.json.bak at mode 0644, and nothing ever deletes it.

**Scenario.** I reproduced this end to end with a scratch Go test inside a copy of the module: wrote a v5 data/config.json (mode 0644) containing SECRET-ACCESS-TOKEN and SECRET-REFRESH-TOKEN into a 0750 data/, then ran config.NewService + creds store + the exact six-migration chain from migrateConfig. Resulting data/ listing: `config.json mode=-rw-r--r-- hasAccess=false hasRefresh=false`, `config.json.bak mode=-rw-r--r-- (0644) hasAccess=true hasRefresh=true`, `secrets.json mode=-rw-r----- (0640) hasAccess=true hasRefresh=true`. So the .bak is exactly the file the migration was meant to retire, at 0644, sitting beside the 0640 secrets.json.

### C10 — P3 — CommandResponse MarshalIndent unconditional, unlike new sibling guard
